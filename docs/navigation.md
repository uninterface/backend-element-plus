# Navigation menus in Element Plus

ElMenu/ElSubMenu/ElMenuItem. The existing private menu-context bridge supplies controlled active/open state and allows full-label vertical flyouts, which native collapsed mode alone cannot express. Persistent mode disables popup behavior. Icon rail uses native collapsed-root styling and hover behavior, with click/touch opening at all depths. Clicking a branch already opened by hover leaves it open; outside interaction, Escape and native hover departure dismiss it. Native expansion notifications preserve pointer focus and ignore already-open ancestors, while keyboard expansion explicitly moves focus into the branch. Rich leading icons and label hiding stay adapter-owned.

All four UiNavMenu presentations are implemented: horizontal, vertical-tree, vertical-popup, and icon-popup. The shared controller owns current/path/requests, while each view owns expansion. Current changes reveal persistent ancestry without opening closed flyouts. Native markup, focus mechanics and styling remain backend-owned. Group and descendant slots preserve leading icons; check selection and shortcut hints are absent from navigation projections.

With `width` omitted, the `horizontal` root fills the parent's offered width.
The `vertical-tree`, `vertical-popup`, and `icon-popup` roots size to their
content up to that width.
Use `width="full"` or `width="content"` to select the root width explicitly
(`navigation.menu.width.v1`). Floating submenus size independently.

Overflowing dropdowns and flyouts scroll inside their native outer popup surface, bounded to the viewport. Each floating level has its own scrollport and contains wheel/touch scroll chaining at its boundaries; nested flyouts remain teleported and can extend beside the parent without being clipped by its scrollport. Native positioning, content height for short menus, keyboard focus and destination activation remain in use. Persistent trees retain content flow inside their containing layout or drawer scrollport. Consumers do not supply popup heights, backend CSS or scroll event handlers.

Navigation and command flyouts register their actual native popper wrappers with Uninterface. Root branches, groups and persistent tree branches forward the enclosing popup scope. The guarded Vite integration for Element Plus 2.14.7 passes the owning surface through ElSubMenu to its native tooltip's `appendTo` prop. This keeps submenu poppers inside the owning dialog or popover while allowing them to extend beyond the parent menu's own scrollport. Review that bridge when upgrading Element Plus.

Horizontal header dropdowns also account for the header's position and native popup offset when sizing their scrollport. A long dropdown can then fit below its trigger instead of being moved to a side simply because its height was capped against the whole viewport. The adapter's native integration limits these header dropdowns to below/above fallbacks and retains native horizontal shifting at viewport edges. Native placement can still choose above when that side has more available space; nested flyouts retain their native sideways placement. The sizing follows opening, header size changes, scrolling and viewport resizing. This uses the existing backend Vite integration and requires no additional application configuration.

Icon-popup uses labelled flyouts and accessible root names; missing root destination icons receive neutral menu-item artwork without changing modes. Navigation labels are required. Responsive selection is application-owned; UiNavbar does not automatically collapse.

The existing application-owned theme/configuration and stylesheet ordering continue to apply; there are no new business-side spacing, caret or native-widget props. See this backend's customization guide for toolkit settings actually consumed by the adapter.

Focused shared DOM tests cover the four presentations, three levels, icons, command-metadata isolation, current/breadcrumb synchronization, synchronous link interception, single request dispatch and accepted/refused navigation. DOM checks do not establish browser geometry, animation, mobile/RTL placement or assistive-technology acceptance.

Menu icon columns use the native menu width and a square glyph with one native-sized label gap. Rich-content wrappers keep icons outside Element Plus's collapsed label-hiding selectors; rail labels use one navigation-owned hover/focus hint, with Escape dismissal and overlay containment; no native title tooltip is added alongside it. Open branches suppress their hint. Floating navigation menus use Element Plus’s compact horizontal-popup row height and padding at every depth, including vertical flyouts and icon-rail flyouts. The height follows --el-menu-horizontal-sub-item-height (36px by default); icons do not increase it. Persistent sidebar/tree rows retain their native vertical sizing. Full-label vertical flyouts use sideways submenu arrows.

Inside UiNavbar, horizontal navigation stretches to the containing row's height (including taller action controls). The navbar owns the outer bottom border, and the menu retains its native active underline at that edge. Standalone horizontal menus retain their own border. Ordinary vertical sidebar borders remain native.

Backend-owned regression coverage mounts the real travel example with the complete stylesheet, verifies that collapsed selectors do not hide icons, traverses the native hover path through level three, checks hover-followed-by-click and click-only activation. Browser checks cover actual glyph/label geometry, pointer travel and header-edge alignment; these are separate from DOM interaction checks and do not by themselves establish user visual acceptance.

The backend-owned scrolling browser suite mounts overflowing and short menus through the real core/backend assembly. It checks wheel scrolling and both boundaries across all floating presentations in LTR/RTL, independent nested scrolling, keyboard revelation of offscreen destinations, activation, dismissal and viewport resizing. A Chromium-specific synthetic touch scenario checks scrolling and boundary containment; physical-device, other-engine and assistive-technology review are separate from that evidence.

Vertical roots and all persistent tree levels retain a leading icon column, including empty decorative slots. This keeps hierarchy independent of icon presence and supports consistent icon coordinates across vertical modes. Independent floating surfaces retain per-level icon-presence decisions. Rail labels appear on hover/focus; grouped headings retain hidden accessible text without widening the rail. Fallback artwork is a view projection, never a source mutation.

Drawer-based navigation is not a UiNavMenu presentation. Support for a hamburger trigger, drawer container and vertical hierarchy composition is planned; its public API and coordination solution remain undetermined.

Root navigation renders a logical themed separator unless an eligible UiNavbar or explicitly designated UiRegionLayout navigation region owns the adjoining boundary. The backend surface coordinates allocation transitions, focus and rail hints through useUiNavigationPresentation; it retains native row/icon geometry. Reduced motion suppresses transitions. DOM regressions cover ownership, fallbacks, expansion retention and hints. Compare geometry, focus and reduced-motion behavior in a browser.

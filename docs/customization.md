# Customize the Element Plus backend

[Documentation index](README.md) · [Application setup](setup.md)

This adapter uses Element Plus 2.14.7. Native CSS variables provide a simple
application-owned customization path. Toolkit configuration options are not all
exposed by the adapter.

## One application stylesheet

Create `src/ui.theme.css`:

```css
@import '@uninterface/backend/style.css';

:root {
  --el-font-size-base: 15px;
  --el-border-radius-base: 6px;
}
```

Replace the direct backend stylesheet import in `src/main.ts` with
`import './ui.theme.css'`. Keep application initialization and shared color-mode
setup unchanged. Import core's stylesheet separately when using its utilities.
The example changes native base text sizing and radius where consumed; it does
not guarantee that every component uses those tokens for every part.

The backend supplies document typography, including popups outside UiApp. For an
application font, set `--uninterface-font-family` after the default import and supply any additional assets. This updates ordinary content and native font tokens together. The stable stylesheet maps the application override to both document and component typography; no font import is needed for an application-owned stack.

## Palettes and dark appearance

Element Plus exposes CSS variables for semantic palettes, text, surfaces,
borders and component details. A primary palette includes
`--el-color-primary`, `--el-color-primary-light-1` through `-light-9` and
`--el-color-primary-dark-2`. These shades are generated by Sass, not recalculated
in the browser when the base variable changes. Provide a coordinated palette,
including the appropriate dark-mode values, instead of replacing only its base.

The backend imports native `.dark` variables. Theme overrides must distinguish
light and dark where necessary and account for selector/cascade precedence.
Keep rules document-wide so teleported controls inherit them; use Uninterface's
color-mode control to select the mode.

## Configuration and layout limits

Element Plus's ConfigProvider supports native size and selected component
configuration. This adapter currently supplies locale through that provider but
does not offer a presentation-options factory. There is no supported one-file
native size/defaults configuration path yet. Do not recreate the locale bridge or
install a second global toolkit plugin just to change size.

Native component size is also distinct from layout spacing: this adapter uses an
8px peer gap, while UiContent uses `--el-main-padding` with a 20px fallback. A
native size change would not automatically make the entire composition compact.

The backend imports compiled component CSS, document reset and dark variables.
Element Plus's custom Sass build is a toolkit facility, but replacing those
imports without duplicating styles is not currently an exported adapter path.
Use CSS variables for simple customization. Native namespace changes and private
adapter selector overrides are not supported customization contracts.

References: [Element Plus theming](https://element-plus.org/en-US/guide/theming.html)
and [ConfigProvider](https://element-plus.org/en-US/component/config-provider.html).

## Verify a customized presentation

Check the same business components with and without your customization: filled
and outline buttons, disabled/loading states, field help/errors, select and menu
popups, icons, layout wrapping and scrolling. Confirm visible keyboard focus and
readable text. Check both supported color modes, including an already-open popup.
Do not infer whole-application coverage from a single button or claim WCAG
conformance from a theme's name. Customization must preserve Uninterface's model,
validation, selection and interaction contracts.

Keep theme authoring in application setup and styles; business views should not
need native toolkit props or per-component CSS to activate the theme. An existing
color role can be recolored without changing its meaning. Adding a role requires
backend implementation and capability support across all relevant components;
CSS alone does not extend Uninterface's theme vocabulary.

## Portable card hierarchy customization

For changes that should survive switching backends, configure a shared strategy in an application-owned Vue composition; no additional stylesheet is required:

```vue
<script setup lang="ts">
import { UiStrategy, uiCardPresentation } from '@uninterface/uninterface'
const cards = uiCardPresentation({
  [-2]: { color: 'primary', border: 'double' },
  [-1]: { color: 'primary', elevation: 'flat' },
  1: { header: 'band', density: 'compact' },
  2: { color: 'secondary', surface: 'tinted' },
})
</script>
<template><UiStrategy :use="cards"><slot /></UiStrategy></template>
```

Place the application's cards under this composition. Omitted properties retain the shared defaults. Each UiCard can override its effective role with color, or explicitly request neutral with :color="null". Customizing palette values remains an application theme task using the setup above; raw CSS/native variant names do not belong in this map. The same configuration works across conforming adapters, with each retaining its own concrete theme values. [Presentation mappings](presentation.md#cards-and-hierarchy) specify which native values are consumed. Test nested/peer cards, headerless units, both color modes and narrow layouts before adopting a custom profile.

## Default font delivery

Import a selected font.css or font-bundled.css entry first, then the stable backend style.css. Omit font imports for system or application-owned fonts, using --uninterface-font-family for a complete override. See [typography](typography.md) for all four choices, setup steps, CSP sources, licenses and limits.

The ordinary font setup offers four choices: backend or Uninterface default, each with Network or Bundled delivery. Import one font entry before the stable backend stylesheet, following [typography](typography.md); the Uninterface choices require the optional `@uninterface/fonts` package.

## Shared input frame coverage

Element Plus has no generic public input frame. This adapter reuses el-input/el-input__wrapper presentation and native input/size tokens, with a wrapper focus/error projection. It does not mount a hidden ElInput or enable native validation. Feedback descriptions use the existing field-presentation service, including delayed native error visibility. Native class compatibility must be checked on upgrades.

The frame follows the input theme through the supported setup described above; private adapter selectors are not a stable public styling API. Check ordinary inputs beside the compound frame under the chosen light/dark theme, sizes, focus, invalid, disabled and readonly states. Interior part wrapping is adapter-owned and is not a global layout-spacing customization contract. See [presentation mappings](presentation.md#shared-input-frames) for limits.


## Drawers and popovers

UiDrawer (modal and retained panel modes) and UiPopover consume this backend's normal surface, typography and color-mode setup. The adapter renders native-themed content over browser dialog/manual-popover hosting so Uninterface remains the only lifecycle and stacking owner. Application styles load after backend style.css; preserve hidden/inert behavior, bounded scrolling, focus treatment and core-owned stacking when customizing. Popups are teleported to body or the owning overlay; scope application theme variables accordingly. Toolkit gesture/snap-point/resizing options and docked/compact drawer allocation are not exposed. Layout peer spacing remains owned by the existing layout components.

UiPopover retains Element Plus’s default visible arrow using `.el-popper__arrow` directly inside the native popper surface, with resolved `data-popper-placement`. Existing light/dark border/background tokens apply. The adapter positions the arrow toward the anchor after flips and viewport clamping, outside the scrolling body; no application arrow markup or business prop is required.

## Remaining popup-arrow limits

The general UiPopover now retains its native arrow. Scalar/range calendar popups and UiSuggestions still explicitly suppress arrows even though their native Popover/Autocomplete counterparts supply them by default; these are remaining presentation gaps. Ordinary UiTooltip and select/multiselect use native defaults. Command-menu popup presentation follows native ElSubMenu, which intentionally omits its pointer. See the core native-arrow presentation principle; do not repair these gaps with business-side CSS.


### Navbar row sizing

Horizontal UiNavbar uses the native `--el-menu-horizontal-height` token as its minimum block size, including when the navbar contains ordinary links instead of UiNavMenu. It adds no vertical padding around a native menu row. Taller slot content and wrapped groups can grow beyond the minimum; the navbar works inside a raised UiRegionLayout without application inset compensation.

An application stylesheet loaded after backend style.css can set `:root { --el-menu-horizontal-height: 64px; }` to customize both menu rows and the navbar minimum. Existing scoped native token overrides remain supported. Verify ordinary links, brand-only content, native menus and taller actions at narrow/wide widths; preserve content growth and visible focus rather than replacing the minimum with a fixed height.

Vertical side navbars stack their groups explicitly and use `--el-menu-base-level-padding` for block insets as well as inline insets. They do not retain the horizontal menu-row minimum. Verify that increasing the side allocation width does not turn these groups into a row.
